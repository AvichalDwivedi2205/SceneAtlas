# Full-screenplay processing

The demo requirement is a complete 100-page screenplay upload and breakdown on a shared canvas. The upload size limit alone is not acceptance evidence. The live test must compare every resulting scene to a reviewed source inventory, reach the last source page, and verify another person can use the same board.

## Processing contract

- English screenplays with selectable PDF text or UTF-8 text, up to 300 PDF pages, 50 MB, 1,200,000 extracted characters, and 300 detected scenes. Scanned and encrypted PDFs return an actionable error. These are enforced limits, not a claim that every maximum-sized combination has been stress-tested.
- PDF layout extraction preserves source reading order and physical PDF page numbers, including title pages. INT./EXT. headings and paired, numbered production slugs establish scene identity. A continued slug stays with its scene; explicitly omitted numbered scenes do not become cards. Non-screenplay prose needs adaptation first.
- Intake reads all pages and reports the indexed scene count. It does not generate an inferred story synopsis or assume the producer's location, crew, equipment, budget, or schedule. The producer chooses the entire screenplay or explicit scene numbers/ranges.
- Every selected scene is partitioned into contiguous parts of at most 10,000 characters. A model request contains at most six parts and 24,000 source characters, with no prior model-response history. Long scenes are split without dropping their remaining text.
- Gemini enriches setting, time, interior/exterior, and story needs. Exact source headings, scene identity, source page spans, excerpts, and unknown shooting durations are assembled by code. A response missing, duplicating, or inventing a part is rejected.
- Valid batches are saved privately in Convex. A SHA-256 key includes source parts, confirmed inputs, model, and pipeline version. Retry reuses matching saved batches on the same board. Changed inputs, cancelled jobs, revoked membership, and cross-board access cannot write or read a live run's checkpoint.
- Scene cards publish atomically only after all selected parts pass validation. Partial model work stays out of the public board. Run history stores the completed count; versioned scene records hold the content. Graph connections use indexed lookups and one placement scan per publication.
- Cloud Run sends progress/heartbeat callbacks during slow model calls and closes the remote stream when the run stops accepting events. A 25-minute worker budget leaves time to save a useful failure before the Cloud Tasks 30-minute deadline. Retry resumes saved batches.
- Large scene groups use a compact initial grid. The canvas renders visible cards on boards above 80 nodes, supports zooming out to the full graph, and keeps scene navigation horizontally scrollable.

## Acceptance harness

`e2e/live-screenplay-scale.spec.ts` runs real Clerk, Convex, Cloud Tasks, Agent Engine, and Gemini. It uploads the actual PDF through the browser, confirms the entire screenplay, optionally cancels after a saved batch and retries, reloads while processing, compares every final scene to the source inventory, checks two editors' board state, navigates to the last scene, and verifies a second editor's note reaches the owner's subscribed board. Auth traces are disabled. Test boards are archived and test users removed.

Provide a private PDF and a reviewed expected JSON file:

```json
{
  "pages": 100,
  "sceneCount": 80,
  "batchCount": 14,
  "scenes": [
    {
      "number": 1,
      "heading": "INT. ARCHIVE - DAY",
      "pageStart": 1,
      "pageEnd": 2,
      "excerpt": "Exact extracted excerpt, at most the first 1600 characters."
    }
  ]
}
```

Include every expected scene, using physical PDF page numbers. The example above shows only the shape. Independently review the source inventory; a manifest generated by the same parser is insufficient on its own to detect a parser omission. For a numbered shooting script, compare a second PDF extractor's numbered slugs and starting pages and verify the sequence is complete.

```sh
SCENEATLAS_SCALE_TEST=1 \
SCENEATLAS_SCALE_PDF=/absolute/path/screenplay.pdf \
SCENEATLAS_SCALE_EXPECTED=/absolute/path/expected-scenes.json \
SCENEATLAS_E2E_URL=https://sceneatlas-black.vercel.app \
bunx playwright test e2e/live-screenplay-scale.spec.ts
```

Add `SCENEATLAS_SCALE_INTERRUPT=1` for recovery acceptance. Ordinary model usage applies. Reports and screenshots are written under `/tmp/sceneatlas-scale-<pages>-*`; PDFs and source excerpts are not bundled into the repository.

## Scope of evidence

Large-upload acceptance covers intake, complete scene breakdown, source mapping, saved-batch retry, canvas navigation, and collaboration. It does not claim that location research, scheduling, permits, or packet generation for every scene in a feature have all been completed or load-tested. Those stages retain their producer-input and provider-quota requirements.

The current deployment still uses Clerk development credentials, and Convex reports account usage above its Free-plan limits. Resolve quota headroom before relying on an uninterrupted public demo. No accounts were created to bypass provider quotas.
